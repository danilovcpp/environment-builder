# UI Style Guide

**Версия:** 1.0  
**Платформа:** WPF / .NET  
**Темы:** Light / Frost и Dark / Midnight  
**Назначение:** обязательная дизайн-спецификация для AI-агентов, реализующих интерфейсы.

> Палитры нормализованы по светлому и тёмному макетам. Значения HEX — рекомендуемые дизайн-токены для разработки, а не обещание точного извлечения каждого пикселя из изображения. При расхождении скриншота и документа использовать токены из этого файла.

## 1. Дизайн-концепция

Профессиональный, компактный desktop-интерфейс для управления локальными окружениями, сервисами и тестовыми данными. Визуальный характер: **clean enterprise / developer tools**, холодные нейтральные поверхности, синий как единственный основной акцент, минимум декоративных элементов.

- Светлая тема — чистые белые карточки на очень светлом серо-голубом фоне.
- Тёмная тема — **глубокий navy/charcoal**, не абсолютный чёрный, с немного более светлыми панелями.
- Одна и та же визуальная иерархия, сетка, размеры и компоновка в обеих темах. Переключение темы не должно менять layout.
- Акцентный синий обозначает основное действие, выбранный раздел, активный фильтр, ссылки и фокус.
- Цвета состояний (зелёный, янтарный, красный, фиолетовый) используются **только семантически**.
- Интерфейс остаётся плотным, но с читаемыми отступами и чётким разделением областей.

### Как трактовать поверхности

**Light:** рабочее поле светло-серо-голубое; панели белые; sidebar отдельно тонирован.  
**Dark:** рабочее поле самое тёмное; sidebar и карточки на 1–2 уровня светлее; поднятые карточки ещё чуть светлее. Для иерархии применять разные поверхности и тонкие границы, **не тяжёлые тени и не яркие градиенты**.

## 3. Семантические цвета статусов

| Семантика | Light: текст | Light: фон | Dark: текст | Dark: фон |
|---|---|---|---|---|
| `Success` | `#076B43` | `#E2F5EA` | `#66E3AF` | `#103C31` |
| `Info` | `#115FDB` | `#E5F0FF` | `#72B7FF` | `#123253` |
| `Warning` | `#965400` | `#FFF0D1` | `#FFC66D` | `#432F17` |
| `Error` | `#B72C43` | `#FDE8EC` | `#FF8797` | `#48232F` |
| `Neutral` | `#54657A` | `#EEF2F6` | `#ADBFD4` | `#223143` |
| `Purple` | `#7545C8` | `#EFE6FF` | `#CCA4FF` | `#35234F` |

**Применение:**
- `Установлен`, `Готово`, `Валидация пройдена` → `Success`.
- `Загружен`, информационные метки → `Info`.
- `Требует внимания`, неполная конфигурация → `Warning`.
- `Ошибка`, `Не удалось применить` → `Error`.
- `Черновик`, `Недоступен` (без признака ошибки) → `Neutral`.
- `Fantasy`, тематические альтернативные категории → `Purple` по необходимости.

Статус всегда содержит **текстовую метку и/или иконку**. Один цвет не должен быть единственным источником информации.

## 4. Тематические бейджи

Бейджи применяют семантические пары foreground/background из раздела 3:

| Бейдж | Стиль |
|---|---|
| `Office` | `Info` |
| `Generic` | `Neutral` |
| `Fantasy` | `Purple` |
| `Sci-Fi` | `Error` (категория, не ошибка) |
| `Small` | `Success` |
| `Medium` | `Info` |
| `Large` | `Warning` |
| `XL` | `Purple` |

Тематические бейджи в таблице визуально второстепенны. Не оформлять каждую ячейку яркой заливкой.

## 5. Компоненты: обязательные правила

### 5.1. Каркас приложения

- **Sidebar слева:** отдельная вертикальная область с `Sidebar`, визуально отделённая `Border` от рабочего пространства. Ширина 240 px (допустимо 232–256 при настройке).
- **Topbar сверху:** иконка экрана, название, краткое описание и действия в одной горизонтальной структуре; высота ориентировочно 72 px.
- **Main content:** `Canvas`, с панелями `Panel`; между основными блоками 12–16 px.
- **Context sidebar справа:** самостоятельная колонка, `ContextPanel`, ширина ориентировочно 384 px, не вложенная в центральную content-карточку. Должна скрываться/сворачиваться. Вертикальная граница `Border`.
- **Bottom status bar:** отдельная, постоянно видимая полоса по всей нижней ширине окна, высота 28–32 px, фон `StatusBar`, верхний разделитель `Divider`.

### 5.2. Навигация

- Default: без заливки, текст `TextSecondary`, иконка `IconPrimary`.
- Hover: подложка `Hover`.
- Selected: подложка `Selected`, текст/иконка `AccentText`, тонкая вертикальная полоса слева `Accent` шириной 3 px.
- Нет крупных цветных плашек на всех пунктах меню; выделен только текущий.

### 5.3. Кнопки

- **Primary:** фон `Accent`, foreground `OnAccent`, радиус 7–8 px; только для ведущего действия (например, «Применить к окружению»). Остальные важные действия оформлять по иерархии.
- **Secondary:** фон `Panel`, текст `TextPrimary`, граница `Border`.
- **Tertiary / Ghost:** без постоянной заливки, текст `TextSecondary`; при hover `Hover`.
- **Destructive:** использовать `Error` для подтверждённого опасного действия, но не делать постоянно яркой обычную кнопку «Удалить».
- Disabled: пониженный контраст, отсутствие hover/pressed, запрет выполнения действия.
- Все иконки 16–18 px, промежуток текст–иконка 6–8 px.

### 5.4. Таблицы и списки

- Фон `Panel`; header `PanelMuted`; разделители `Divider`.
- Высота строки данных 36–40 px; заголовок 32–36 px.
- Hover row → `Hover`; selected row → `Selected`; selected + focused → видимый акцент.
- Основной текст ячейки `TextPrimary`, метаданные `TextSecondary`.
- Иконки действий обычные `IconMuted`, при hover `AccentText`.
- Не применять сплошные яркие цветные заливки к строкам.
- Длинные тексты обрезать с ellipsis и tooltip; числа выравнивать консистентно.

### 5.5. Формы, вкладки, фильтры

- Input/Search: `Input` + `Border`, border radius 8 px; placeholder `TextTertiary`; focus → `FocusRing` толщиной 2 px.
- Вкладки: активная — `AccentText` и нижняя линия `Accent` (2 px); остальные `TextSecondary`.
- Filter chips: неактивные — `PanelMuted` + `Border`, активные — `Accent` + `OnAccent`.
- Badge: плотная компоновка; высота 20–22 px; скругление 999 px, размер текста 11–12 px.
- Положительное подтверждение: фон `Success.Background`, текст `Success.Foreground`, тонкая обводка в той же цветовой семье.

### 5.6. Правая контекстная панель

- Содержимое меняется по текущему разделу, но сама панель — часть общего layout.
- Заголовок и кнопка сворачивания присутствуют всегда.
- Несколько логических секций отделять `Divider`, не создавать матрёшку из большого количества карточек.
- При недостатке высоты содержимое скроллится **внутри** контекстной панели; Topbar и StatusBar остаются на месте.

## 6. Типографика, размеры, иконки

**Шрифт:** `Segoe UI Variable` (если доступен), fallback `Segoe UI`. Вес 400/500/600/700, без необычного display-шрифта.

| Роль | Размер | Начертание |
|---|---|---|
| Заголовок экрана | 22–24 px | Semibold / 600 |
| Заголовок секции/панели | 15–16 px | Semibold / 600 |
| Заголовок карточки или группы | 13–14 px | Semibold / 600 |
| Основной текст, таблица | 12–13 px | Regular / 400 |
| Метаданные, вспомогательный текст | 11–12 px | Regular / 400 |
| Ключевые KPI-значения | 18–20 px | Semibold / 600 |
| Подписи бейджей | 11–12 px | Medium / 500 |

**Единицы:** размеры в этом документе заданы в логических пикселях WPF (DIP), а не в физических пикселях монитора.

**Отступы:** базовая сетка 4 px, обычный шаг 8 px. Между полем и подписью 4–6 px, между связанными элементами 8 px, между карточками 12 px, между секциями 16 px. Внутренние отступы панелей 12–16 px.

**Скругления:** input/button 7–8 px, panel 8–10 px, small badge pill. Не использовать чрезмерно большие радиусы.

**Иконки:** единая stroke-библиотека (предпочтительно Lucide или аналогичный единообразный набор), размер 16–20 px, толщина stroke примерно 1.75–2 px. Цвет берётся из семантических токенов. Не смешивать нестыкующиеся стили иконок.

## 7. WPF — правила реализации для AI

1. Создать единый слой ресурсов `Themes/Light.xaml`, `Themes/Dark.xaml`, `Themes/Components.xaml`, `Themes/Typography.xaml` (или эквивалентную структуру).
2. Во всех визуальных компонентах использовать `DynamicResource Brush.*` или централизованные theme-aware ресурсы. **Никаких локальных HEX в XAML экранов, view models и code-behind.**
3. Имена ресурсных ключей одни и те же в обеих темах, например `Brush.Canvas`, `Brush.Panel`, `Brush.TextPrimary`, `Brush.Accent`, `Brush.SuccessBackground`.
4. Оттенки при hover/pressed/selected задавать явно ресурсами темы; не вычислять случайным умножением RGB в каждом контроле.
5. Переключение темы реализовать заменой theme ResourceDictionary без перезагрузки экрана и потери состояния. Поддержать Light / Dark / System, если системный режим есть в требованиях.
6. Общие стили для `Button`, `TextBox`, `ComboBox`, `TabControl`, `DataGrid`, `ScrollBar`, `ToolTip`, `CheckBox` и собственных карточек. Стили состояния и клавиатурный фокус обязательны.
7. Не использовать цветовую логику в view model. VM отдаёт семантическое состояние (`Installed`, `Draft`, `Error`); View конвертирует состояние в style/resource согласно теме.
8. Использовать `Grid` с фиксированными/звёздочными колонками для каркаса; использовать `DockPanel` там, где он упрощает status bar/topbar. Не создавать фиксированную пиксельную разметку, ломкую при ресайзе.
9. В таблицах использовать виртуализацию и переиспользуемые шаблоны для больших наборов данных.
10. Переключение темы не должно сбрасывать выделение, позицию прокрутки или введённые данные.

**Пример ресурсов (должен существовать отдельно для каждой темы):**

```xml
<Color x:Key="Color.Canvas">#F4F7FB</Color>
<SolidColorBrush x:Key="Brush.Canvas" Color="{StaticResource Color.Canvas}" />
<Color x:Key="Color.Accent">#0869EF</Color>
<SolidColorBrush x:Key="Brush.Accent" Color="{StaticResource Color.Accent}" />
```

**Пример потребления в компоненте:**

```xml
<Border Background="{DynamicResource Brush.Panel}"
        BorderBrush="{DynamicResource Brush.Border}"
        BorderThickness="1"
        CornerRadius="9" />
```

Цвета статусов должны иметь пары отдельных brush-ресурсов: `Brush.SuccessForeground` + `Brush.SuccessBackground` и аналогично для остальных статусов.

## 8. Требования к качеству и визуальная приёмка

- Реализованы обе темы; переключение работает в runtime без рестарта.
- Все основные токены из разделов 2–3 есть в ресурсах обеих тем.
- Один экран использует одну и ту же иерархию компонентов в обеих темах.
- Нет hardcoded colors в Views/ControlTemplates, кроме определений ресурсов палитры.
- Весь важный текст имеет контрастность не ниже **4.5:1**, крупный текст и ключевые графические элементы — не ниже **3:1**; обязательна проверка на фактическом фоне конкретного элемента.
- Поддержаны Hover / Pressed / Selected / Focused / Disabled и визуальные состояния ошибок.
- Все кликабельные элементы различимы, keyboard focus виден; статусы не кодируются одним лишь цветом.
- Layout сохраняет целостность при типичных desktop-размерах и масштабировании ОС 100/125/150%.
- Заголовок, навигация, правая контекстная панель и нижний status bar визуально и структурно отделены от контента.
- UI-компоненты не дублируют стили вручную — используются единые ресурсы и переиспользуемые стили.

## 9. Инструкция AI-агенту

> Используй этот документ как обязательный источник визуальных правил при реализации WPF-интерфейса Environment Builder. Не придумывай новые цвета, размеры, скругления или паттерны управления, если они уже определены здесь. Реализуй семантические ресурсы Light и Dark в первую очередь; затем создавай переиспользуемые стили компонентов и только после этого экраны. Любое новое визуальное состояние оформляй через общую систему токенов. При конфликте между локальным стилем и общим style guide приводи локальный стиль к общему. Не жертвуй читаемостью, доступностью и предсказуемым поведением ради декоративных эффектов. После каждого изменения UI проверяй внешний вид в обеих темах, различимость состояний и отсутствие визуальных регрессий.
