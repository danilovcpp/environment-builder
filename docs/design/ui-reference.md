## Инвентаризация до изменений

Sidebar 208 DIP вместо пропорций эталона; правая панель 240 DIP с общей
строкой recovery вместо выбранного контекста; нет иконки страницы и ведущих
действий в шапке. Строка окружения — высокая вертикальная карточка с четырьмя
текстовыми кнопками. Поиск и фильтры занимают несколько строк, повторная загрузка
видна постоянно. Редактор — длинная последовательность раскрытых форм;
Inspect отдаёт большую часть высоты пояснениям вместо таблицы/логов. SeedPacks,
Settings и Diagnostics — текстовые заглушки. Цветовые semantic tokens и базовые
interaction states уже существуют, их следует переиспользовать.

## Нормализованная геометрия

- Sidebar 240 DIP; topbar минимум 72 DIP; status bar 30 DIP.
- Контекст 320 DIP при 1280, 384 DIP от 1500; в свёрнутом виде 48 DIP.
- Поля рабочей области 16 DIP, интервалы 12 DIP; панели radius 8, border 1.
- Контрол 32 DIP, строка таблицы 38 DIP, header 34 DIP; row actions 30×30 DIP.
- Page title 24/600, section 16/600, body 13, metadata 12; Segoe UI Variable/Segoe UI.
- Light: Canvas #F4F7FB, Panel #FFFFFF, Sidebar #F0F4F9, Border #DEE7F0,
  Accent #0869EF. Синий эталона нормализован для читаемости белой подписи.
  Dark использует существующие semantic пары при идентичной геометрии.
- Цветные badges второстепенны, unknown/нет измерения не заменяются нулями.
- Badge: min-height 22 DIP, radius 11 DIP. Огромный web-radius 999 в WPF
  давал эллипс вместо капсулы и заменён измеренным радиусом.
- Клавиатурный фокус, hover/pressed/selected/disabled/error — общие styles.

## Допустимые адаптации

Четыре основных раздела вместо дополнительных пунктов макетов: Compose и editor
контекстные. UUID только для чтения, Save не запускает Docker. Вместо придуманных
CPU/размеров/процентов показываются доступные данные и явное отсутствие измерений.
На узком окне контекст сворачивается, формы и текстовые планы прокручиваются;
важные команды остаются вне прокрутки. Диалоги допускают большую высоту и
прокручиваемые details, чтобы точные последствия не терялись ради плотности.

## Граница подготовленных представлений

Библиотека показывает сохранённые метаданные SeedPack; импорт/удаление/apply и
постраничный payload preview подключаются в US7/T118. Settings показывает реальную
библиотеку компонентов, пути и смену темы; изменение defaults/версий относится к
US8/T127. Diagnostics показывает реальное состояние хранилища и recovery summary;
детальные recovery actions и экспорт — US10/T148. Недоступные действия содержат
объяснение, не выглядят исполняемыми. Встроенного demo-контента в production нет.

## Проверка

Fixture stores: `demos/fixtures/ui-reference/`; проверки: `UiReferenceTests.cs` и
существующие keyboard/FlaUI suites US1–US5. Evidence сохраняется в
`artifacts/ui-refinement/20261028/`: before, after, reference-review.md, verification.md.
Checkpoint и фактический DPI фиксируются по выполненным проверкам, без предположений.

**Результат 2026-10-28:** Phase 7a проверена в Light/Dark при 1280×720 и
1672×941 DIP, текущий фактический DPI 144 (150%). По прямому уточнению
пользователя «не надо проверять при других масштабах» дополнительные масштабы
исключены из этого запуска; системный масштаб не менялся. Полная release-матрица
QR-003/T158 не объявляется выполненной. Предварительный эксперимент с DPI-unaware
тестовым HWND в `after-96/` не используется как подтверждение масштаба дисплея 100%.

Снимки каждого экрана просмотрены и сопоставлены с макетами. В
`artifacts/ui-refinement/20261028/comparison.html` доступны исходный UI, новый UI и
референс рядом. `reference-review.md` фиксирует результат и допустимые адаптации
по каждому экрану. В `before/` находятся первоначальные снимки и повторная
визуализация исходников HEAD в отдельной архивной копии при одинаковом размере
1280×720 DIP и DPI 144. Это отдельный layout-capture, не повторная приёмка старой
функциональности. UUID, содержимое fixtures и состояния могут различаться;
сравнивается геометрия областей, а не точное совпадение пикселей данных.

Изображения не перерисованы: WPF RenderTargetBitmap сохраняет client area с
фактическим DPI. Снимки Inspect используют production XAML shell/page/header
с тестовыми observation/command данными; фактические keyboard/navigation/close
сценарии дополнительно проходят FlaUI в отдельном процессе с изолированным store.

Проверены compact rows (red: 227.31 DIP → 38 DIP), раскрываемый состав,
фильтры/scroll/selection, длинные имена, свёрнутый контекст, empty/loading/error/
unreadable/unknown/offline/partial, вкладки Inspect и диалоги. Найденная регрессия
validation → свёрнутые параметры исправлена: раскрывается нужный instance/tab,
поле получает keyboard focus после создания визуального дерева; поздние callbacks
после ухода со страницы отбрасываются. Theme switch сохраняет draft/route/selection/
scroll/progress. Значимые пары текста, semantic badges и focus проверены на
фактических поверхностях (4.5:1 для текста, 3:1 для иконок/фокуса).

Подготовленные SeedPacks/Settings/Diagnostics показывают сохранённые данные,
empty/unavailable states и причины недоступности. Они не закрывают T118/T127/T148.
В интерфейсе причины сформулированы для пользователя без номеров задач.
